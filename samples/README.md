# Sample and test data

Everything in this folder is **synthetic**. It exists so the dashboard can be
developed and tested without spending API credits, and without using a real
person's resume.

## `sample-resume-jordan-kim.pdf`

A fictional resume used to exercise the upload flow end to end. Jordan Kim does
not exist. The employers named in it are real companies, but the roles,
dates and accomplishments are invented.

Use it to try the Upload a resume button without uploading your own resume.

## `test-fixtures/`

Deliberately awkward inputs used to test the file reader:

| File | What it tests |
| --- | --- |
| `alex-morgan.docx` | Word extraction, including tabs, line breaks and XML entities |
| `broken.docx` | A `.docx` with no `word/document.xml`, which must produce a clear error |
| `plain-resume.txt` | The plain-text path |
| `tiny.txt` | A file too short to be a resume, which must be rejected |

## `resumes/*.txt`

Twelve fictional resumes, none of them anything like the board owner's, for
testing the upload flow end to end against the real API. Each is a person the
board was not built for, which is the point: the tailoring has to work for them
too, and for most of them the right answer is "this board is the wrong board,
here are employers in your field".

| File | Who | What the board should do |
| --- | --- | --- |
| `nurse-slc.txt` | An ICU nurse in Salt Lake City staying in nursing | Field mismatch: suggested health systems lead the page |
| `austin-cs-ms.txt` | A CS master's student in Austin with an ML focus | Geography re-maps; degree bars are no obstacle |
| `denver-career-changer.txt` | A six-year teacher in Denver with a 2026 analytics master's | Six years count; new-grad programs are the wrong cohort |
| `byu-accounting-it-audit.txt` | A BYU accounting senior in Provo on the IT-audit track | Local mode, no suggestions, but no University of Utah extras |
| `bootcamp-remote.txt` | A bootcamp graduate in rural Montana, no degree, remote only | Remote-first mode |
| `experienced-de-slc.txt` | A five-year data engineer in Salt Lake City | Over-qualified: the seniority cap never fires |
| `mech-engineer-logan.txt` | A Utah State mechanical engineering senior relocating to Salt Lake | Field mismatch: aerospace and manufacturing employers lead |
| `chemistry-lab-slc.txt` | A University of Utah chemistry senior, two years of bench work | Field mismatch with the Utes extras shown: labs and diagnostics lead |
| `journalism-denver.txt` | A CU Boulder journalism graduate in Denver | Field mismatch and re-mapped geography: newsrooms lead |
| `ux-designer-slc.txt` | A Weber State design BFA in Ogden heading for product design | Adjacent to the board's product roles; Utah design employers added |
| `marketing-analytics-boise.txt` | A Boise marketing coordinator one year in, moving toward analytics | One year counts; Boise and remote employers added |
| `civil-engineer-intl-phoenix.txt` | An international civil-engineering master's student in Phoenix | Field mismatch; programs that refuse sponsorship are the wrong cohort |

Every name, employer history and date is invented. A real run costs about
$0.30 each on the default settings.

## `cases/*.json`

Fifteen mock API responses, generated by `make-cases.py` from the board itself so
they always cover every employer (the page rejects a response that covers fewer
than 80% of them, which is how the previous hand-written cases died when the
board grew). Twelve are what Claude would plausibly return for the twelve resumes
above; three exercise the page's defences:

| File | What it covers |
| --- | --- |
| `nurse-slc.json` … `civil-engineer-intl-phoenix.json` | One per resume above, with scores set by simple rules per persona and suggested employers from the resume's own field and city |
| `hostile-output.json` | Out-of-range scores, unknown and duplicate employers, bad enum values, a suggestion that is really a board employer, 25 suggestions (the page keeps 20), over-long strings, a `javascript:` LinkedIn URL |
| `too-few-companies.json` | 56 of 81 employers, which the page must reject |
| `profile-predates-employers.json` | A profile made before two employers joined the board, which must hide them and say so |

Re-run the generator after adding an employer:

```bash
python3 samples/make-cases.py
```

> **These are fabricated fixtures, not career advice.** The suggested employers
> in them are real companies, but the hiring programs, application windows and
> job titles were written to look plausible for testing. Do not rely on any
> claim in these files. Only a real run against the Claude API produces output
> intended to be acted on, and even then the suggested employers are explicitly
> marked unverified.

### Replaying the cases

`harness.js` replays every case through the page and checks the rules LOGIC.md
promises: the 80% rule, the seniority cap, eight Tier 1 cards, badge
derivation, suggested employers (deduplication, the twenty cap, when they lead
the page), geography relabeling and local mode, the University of Utah extras,
hidden chips, the New this week count, hidden untailored employers, stale
profiles after a newer refresh, and what the page does with hostile output.
The checks are written from the documentation, not copied from the code.

Serve the folder, open the page, and run this in the browser console:

```js
await import('/samples/harness.js'); await JobFinderHarness.run();
```

It prints a table of every check and restores whatever profile was active. No
API key, nothing spent. To replay one case by hand:

```js
const data = await (await fetch('/samples/cases/austin-cs-ms.json')).json();
const T = window.JobFinderTailor;
const profile = T.buildProfile(data, {
  model: 'claude-sonnet-5-5', effort: 'high',
  usage: { input_tokens: 3000, output_tokens: 20000 }, servedBy: 'claude-sonnet-5-5',
});
T.applyProfile(profile);          // T.applyProfile(null) restores the built-in board
```
